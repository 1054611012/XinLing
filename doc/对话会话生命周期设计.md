# AI 对话会话生命周期设计

## 核心原则

- 一次对话 = 一个 session（会话）
- sessionId 由后端首次消息时生成，返回给前端保存
- 前端维护当前 sessionId，后续消息携带，形成连续对话
- 新建对话时，前端主动清除 sessionId，触发后端创建新 session

---

## 完整流程图

```
用户首次打开页面
         │
         ▼
  ┌─────────────────────┐
  │ 前端 currentSessionId = null │
  └─────────┬───────────┘
            │
   用户输入第一条消息，点击发送
            │
            ▼
  ┌─────────────────────────────┐
  │ POST /api/app/chat/send     │
  │ (不传 sessionId)            │
  └─────────┬───────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │ 后端发现 sessionId 为空          │
  │ 1. 生成新的 UUID                 │
  │ 2. 保存会话元数据到 Hash         │
  │ 3. 添加到用户 ZSet 列表          │
  │ 4. 保存用户消息到 Redis List     │
  │ 5. 调用 AI                       │
  │ 6. 保存 AI 回复                  │
  │ 7. 自动生成标题（取用户消息前20字）│
  │ ──────────────                   │
  │ 返回 { sessionId, content }      │
  └─────────┬────────────────────────┘
            │
            ▼
  ┌─────────────────────────────┐
  │ 前端保存 sessionId          │
  │ currentSessionId = res.sessionId │
  │ 渲染 AI 回复                │
  └─────────┬───────────────────┘
            │
   用户输入第二条消息，点击发送
            │
            ▼
  ┌───────────────────────────────┐
  │ POST /api/app/chat/send       │
  │ { content, sessionId }  ← 携带 │
  └─────────┬─────────────────────┘
            │
            ▼
  ┌──────────────────────────────────┐
  │ 后端发现已有 sessionId           │
  │ 1. 保存用户消息到该会话          │
  │ 2. 调用 AI（带上下文记忆）       │
  │ 3. 保存 AI 回复                 │
  │ 4. 更新 ZSet score（排序置顶）   │
  │ ──────────────                   │
  │ 返回 { sessionId, content }      │
  └─────────┬────────────────────────┘
            │
   反复发送... (始终携带同一 sessionId)
            │
            ▼
   用户点击"新建对话"
            │
            ▼
  ┌─────────────────────────────┐
  │ 前端清空 currentSessionId   │
  │ currentSessionId = null     │
  │ 清空本地 messages           │
  │ 回到初始状态                │
  └─────────────────────────────┘
            │
   再次输入消息 → 回到第一步（生成新 session）
```

## API 接口明细

### 发送消息

```
POST /api/app/chat/send

首次发送（不传 sessionId）:
  Request:  { "content": "今天心情不好" }
  Response: { "code": 200, "data": { "sessionId": "xxx", "content": "..." } }

后续发送（携带 sessionId）:
  Request:  { "content": "为什么", "sessionId": "xxx" }
  Response: { "code": 200, "data": { "sessionId": "xxx", "content": "..." } }
```

### 获取会话列表（标题）

```
GET /api/app/chat/sessions?page=1&size=20
Response: { "code": 200, "data": { "list": [...], "total": 35 } }
```

### 加载历史消息

```
GET /api/app/chat/history?sessionId=xxx
Response: { "code": 200, "data": [{ role, content, createTime }, ...] }
```

## 前端需要改动

当前 `ChatPage.vue` 的问题：无 session 管理，每次发送都不带 sessionId，导致后端每次都创建新会话。

### 改动点

```typescript
// 1. 新增状态
const currentSessionId = ref<string | null>(null)

// 2. 加载历史：需要 sessionId 参数
async function loadHistory() {
  if (!currentSessionId.value) return  // 新会话无需加载
  const res = await getChatHistory(currentSessionId.value)
  // ...
}

// 3. 发送消息：携带 sessionId
async function handleSend() {
  const res = await sendMessage({
    content,
    sessionId: currentSessionId.value || undefined  // 首次为 undefined
  })
  // 保存返回的 sessionId
  if (res.data?.sessionId) {
    currentSessionId.value = res.data.sessionId
  }
}

// 4. 新建对话
function newConversation() {
  currentSessionId.value = null
  messages.value = [initialGreeting]
}
```

### 前端类型定义

```typescript
// 发送消息参数
interface SendMessageParams {
  content: string
  sessionId?: string    // 可选，首次不传
  voice?: string
}

// 发送消息响应
interface SendMessageResult {
  sessionId: string
  content: string
}
```

## 数据一致性保证

| 阶段 | sessionId | 后端行为 |
|------|-----------|---------|
| 首次消息 | null/空 | 创建新 session，写入 Hash + ZSet |
| 同会话继续 | 有值 | 追加消息到 List，更新 ZSet score |
| 新建对话 | null/空 | 再次创建新 session |
| 会话列表页 | — | ZSet 分页查询，按 updateTime 降序 |
